# 측정 규칙

실험 결과를 표에 올리기 전에 지킵니다. 앞선 실험 저장소에서 실제로 틀렸던 경우를 규칙으로 만든 것입니다.

## 조건

- 한 번에 조건 하나만 바꿉니다. 실험 README에 고정한 조건과 바꾼 조건을 따로 적습니다.
- 실행 전에 `scripts/doctor.sh` 출력을 결과 파일에 붙입니다. 같은 맥에서 다른 부하가 돌았으면 그 회차는 따로 표시하고 백분위를 섞지 않습니다.
- 캐시 상태를 맞춥니다. 버퍼 풀, 페이지 캐시, 쿼리 캐시를 비우거나 미리 데우는 방식을 정하고 모든 조건에 같게 적용합니다.
- 컨테이너와 볼륨은 실험마다 `scripts/reset.sh`로 처음 상태에서 시작합니다. 앞 실험이 남긴 토픽, 오프셋, 테이블이 다음 결과를 바꿉니다.

## 0과 성공

- 0은 성공과 실패가 같은 모양입니다. 중복 0, 누락 0, 차이 0을 결과로 쓰려면 장애가 실제로 주입됐다는 증거(로그, 오프셋, 리더 전환 기록)를 함께 남깁니다.
- 탐침과 검사 스크립트에는 재시도를 넣지 않습니다. 재시도가 실패를 가립니다.
- 작업 성공 표시와 데이터 정확성을 따로 봅니다. 성공한 작업의 결과도 정답과 대조합니다.

## 지연

- 지연은 평균 대신 p50, p95, p99와 최댓값으로 씁니다. p95는 표본 59개 이상, p99는 표본 299개 이상일 때만 씁니다(표본이 n개일 때 최댓값이 실제 p95 이상일 확률은 1 − 0.95ⁿ이고, n = 59에서 95%를 넘습니다. p99는 n = 299에서 같은 조건이 됩니다).
- 부하는 열린 루프(도착 시각을 미리 정하고, 응답을 기다리지 않음)로 겁니다. 닫힌 루프는 시스템이 느려지면 부하도 줄어 지연을 과소 측정합니다(coordinated omission).

## 판정

- 판정 기준은 실험 전에 README에 적습니다.
- 결과를 본 뒤 기준을 바꾸면 원래 기준의 판정부터 적고, 바꾼 이유와 새 기준의 판정을 그 아래에 적습니다.
- 같은 시뮬레이션을 다시 돌린 결과는 독립 검증이 아닙니다.

## 사례 인용

- 기업 사례의 수치는 원문을 직접 확인한 것만 씁니다. 재게시본이나 요약 글로만 본 사례는 그렇다고 적고 수치를 쓰지 않습니다.
- 공식 문서를 인용할 때는 문서의 표현을 그대로 씁니다. 문서에 없는 단어(예: 문서에 "idempotent"가 없는데 멱등을 권고했다고 쓰기)를 넣지 않습니다.
